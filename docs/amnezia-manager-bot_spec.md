# Amnezia Bot — краткая MVP-спека

## 1. Цель

Сделать небольшой Telegram-бот на Go, через который доверенные пользователи смогут самостоятельно создавать и удалять конфиги AmneziaWG.

Бот работает в Kubernetes-кластере в Санкт-Петербурге, хранит состояние в PostgreSQL и управляет peer'ами на удалённом AmneziaWG сервере. Перед выдачей конфиг автоматически получает split-routing: российские сети идут напрямую, остальные — через VPN.

## 2. Ключевой flow

1. Пользователь открывает бота.
2. Бот проверяет Telegram User ID и доступ к серверу.
3. Пользователь нажимает «Создать конфиг» и задаёт имя устройства.
4. Бот проверяет персональный лимит активных конфигов.
5. Backend создаёт peer на VPN-сервере и получает конфиг.
6. В конфиге заменяется `AllowedIPs` на актуальный список split-routing.
7. В PostgreSQL сохраняются метаданные peer'а.
8. Готовый `.conf` отправляется пользователю в Telegram.

Пользователь также может посмотреть свои устройства и удалить конфиг. При удалении соответствующий peer удаляется с VPN-сервера и помечается отозванным в БД.

## 3. Минимальная архитектура

- **Telegram layer** — команды, кнопки и сообщения.
- **Application service** — проверка доступа и лимитов, создание и удаление конфигов.
- **VPN provider** — небольшой адаптер для управления peer'ами на AmneziaWG-сервере по SSH: создать peer, получить конфиг, удалить peer.
- **Config patcher** — замена `AllowedIPs` в полученном конфиге.
- **PostgreSQL** — пользователи, доступы и метаданные созданных peer'ов.

Приложение остаётся stateless; постоянное состояние хранится в PostgreSQL. Для MVP достаточно одного deployment и одной реплики.

## 4. Основные сущности

### User

- Telegram User ID;
- username для удобства администратора;
- включён или заблокирован;
- лимит активных конфигов.

Признак администратора в БД не хранится: администраторы задаются списком Telegram User ID в ConfigMap.

### Server

- стабильный ID;
- отображаемое имя;
- адрес и параметры доступа по SSH;
- признак доступности для выдачи.

Список серверов задаётся конфигурацией. В MVP сервер может быть один, но код не должен быть жёстко привязан к конкретному адресу.

### UserServerAccess

Связывает пользователя с доступным ему сервером. Позволяет позднее добавить второй VPS без переделки модели.

### VpnPeer

- владелец и сервер;
- ID peer'а на VPN-сервере;
- имя устройства;
- дата создания;
- дата отзыва, если удалён.

Приватные ключи и полный конфиг в БД не хранятся. Конфиг выдаётся один раз; потерянный конфиг пользователь удаляет и создаёт заново.

## 5. Конфигурация

В Kubernetes ConfigMap:

- список VPN-серверов и их публичные параметры;
- список Telegram User ID администраторов;
- лимит конфигов по умолчанию;
- URL источника split-routing списка;
- порог недоступности сервера для алертов и интервал проверок;
- базовые настройки приложения.

В Kubernetes Secret:

- Telegram bot token;
- строка подключения к PostgreSQL;
- credentials для SSH-доступа к VPN-серверу.

Администраторы задаются только через ConfigMap, отдельной роли в БД нет.

## 6. Telegram UX

### Пользователь

- `/start` — проверка доступа и главное меню;
- «Создать конфиг» — запрос имени устройства и выдача `.conf`;
- «Мои устройства» — список активных конфигов и текущий лимит;
- «Удалить» — отзыв выбранного конфига;
- «Инструкция» — короткая памятка по установке AmneziaWG и импорту файла;
- «Пожаловаться / Помощь» — свободный текст обращения, которое уходит администраторам.

Если пользователь не разрешён, бот отвечает «Нет доступа» без раскрытия внутренней информации.

### Администратор

Минимальный набор команд:

- добавить пользователя по Telegram User ID;
- отключить пользователя;
- изменить лимит;
- посмотреть список пользователей и их активные конфиги;
- получать алерты о недоступности серверов и новые обращения пользователей.

Отдельная веб-админка для MVP не нужна.

## 7. Split-routing

При создании конфига бот заменяет строку `AllowedIPs` на готовый список «весь IPv4, кроме российских и приватных сетей». Источник по умолчанию — опубликованный файл `wg-allowed-ips.txt` проекта `amnezia-split-route-sync`.

Список периодически обновляется в фоне и хранится как last-known-good копия. Создание конфига не должно зависеть от доступности внешнего источника в конкретный момент. При запуске у приложения должна быть встроенная или заранее загруженная начальная версия списка.

IPv6 в MVP не поддерживается: его поведение нужно явно ограничить, чтобы трафик случайно не обходил VPN.

## 8. Базовый мониторинг

- Бот периодически проверяет доступность VPN-серверов по SSH.
- Администраторы получают алерты о новых обращениях пользователей и о недоступности сервера дольше порога, заданного в ConfigMap.
- Алертами не спамим: по каждому серверу ведётся одно статусное сообщение, и все обновления (недоступен, восстановлен, новое обращение по этому серверу) редактируют его. Новое сообщение отправляется только при новом инциденте.
- Обращение пользователя пересылается с указанием автора и текста.

## 9. Security basics

- Доступ определяется только по числовому Telegram User ID, а не по username.
- Обычный пользователь видит и меняет только свои конфиги.
- Админские команды доступны только разрешённым администраторам.
- Секреты не хранятся в ConfigMap, репозитории или логах.
- Полные конфиги и private keys не сохраняются после отправки пользователю.
- Управление сервером выполняется по SSH от отдельного пользователя с минимально необходимыми правами (ограниченный sudo для wg-команд), полноценный root-доступ не используется.
- Ошибки пользователю показываются без внутренних адресов, токенов и технических деталей.

## 10. Out of scope

В MVP не входят:

- автоматический failover и миграция пользователей между серверами;
- server groups, балансировка и автоматический выбор VPS;
- веб-админка;
- платежи, подписки и публичная регистрация;
- хранение и повторная выдача старых конфигов;
- детальный мониторинг, аудит и аналитика (базовые алерты и обращения входят в MVP);
- сложные роли и granular permissions;
- автоматическое восстановление рассинхронизации с VPN-сервером;
- полноценная поддержка IPv6.

Это можно добавлять после появления реальной необходимости.

## 11. Acceptance criteria

MVP считается готовым, если:

1. Неавторизованный Telegram User ID не может пользоваться ботом.
2. Администратор может добавить, отключить пользователя и установить ему лимит.
3. Авторизованный пользователь может создать конфиг в пределах лимита.
4. Для созданного конфига реально появляется peer на настроенном AmneziaWG-сервере.
5. Выданный `.conf` импортируется в AmneziaWG и подключается к VPN.
6. В конфиге применён split-routing: российские IPv4-сети идут напрямую, остальные IPv4-сети — через VPN.
7. Пользователь видит только свои устройства и может удалить любое из них.
8. После удаления peer больше не даёт подключиться.
9. Перезапуск pod'а не приводит к потере пользователей и метаданных peer'ов.
10. В БД и логах отсутствуют private keys и полные VPN-конфиги.
11. Администраторы получают алерты о недоступности сервера дольше заданного порога и уведомления об обращениях пользователей; обновления статуса редактируют одно и то же сообщение, а не создают новые.
